# 子 Agent 任务合同

向子 Agent 分配任务时使用以下结构。只填写与当前任务有关的字段。

## 合同结构

### 角色

用简短名称描述该 Agent 的职责。

### 目标

说明该 Agent 独立负责的一个具体结果。

### 输入

列出该 Agent 可以使用的文件、需求、数据、已批准的前置产物或项目状态。

### 权威信息来源

当不同输入之间存在冲突时，说明应以哪个来源为准。

### 预期输出

说明该 Agent 必须返回的产物、决策、实现结果、报告或证据。

### 允许的操作

说明 Agent 可以执行的读取、写入、运行、浏览、检查或沟通操作。

### 禁止的操作

说明哪些操作会破坏独立性、与其他负责人冲突或超出用户授权。

### 所有权

说明该 Agent 可以修改的文件、目录、决策或状态。

### 完成标准

列出能够客观判断任务是否完成的条件。

### 必要证据

列出测试结果、命令输出、检查过的文件、引用、截图、代码差异或其他证明。

## 分派规则

- 每个交付物只能有一个明确负责人。
- 当独立性有价值时，应分离调查、产出、审查和整合职责。
- 不要让两个并行 Agent 修改同一个共享状态。
- 目标应描述需要达到的结果，而不是规定所有实现细节。
- 对重试、无法确认结果的外部写操作和潜在破坏性工作设置停止条件。
- 遇到阻塞时，Agent 应报告问题，而不是自行扩大任务范围。
