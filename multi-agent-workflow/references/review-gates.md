# 审查关卡

只有当某个决定会控制后续工作能否继续时，才使用正式关卡。

## PASS

只有满足以下条件才能返回 `PASS`：

- 必要产物已经存在；
- 验收标准已经满足；
- 必要证据已经检查；
- 不存在阻塞性问题。

可以保留不影响验收标准的轻微限制，但必须明确记录。

## REJECT

当产物存在问题，但能够在当前任务范围内纠正时，返回 `REJECT`。

拒绝结果必须包含：

- 未通过的验收标准；
- 证明问题存在的证据；
- 必须完成的修改；
- 修改后需要重新审查的部分。

当产物已经满足明确要求时，不得仅因为个人偏好而拒绝。

## BLOCKED

以下情况返回 `BLOCKED`：

- 缺少必要输入；
- 缺少工具、环境或访问权限；
- 需要用户做出会实质改变结果的决定；
- 需要执行超出当前授权范围的操作；
- 存在 Agent 无法解决的外部条件。

阻塞报告必须说明恢复工作所需的最小操作。

## 纠正循环

将被拒绝的工作交给有能力修正它的 Agent。

如果保留上下文有助于修正，可以交回原产出者。如果问题来自能力不足或需要保持独立性，可以使用新的产出者。

修改完成后必须重新进行受影响的审查。不得沿用修改前的 `PASS` 结果。

默认最多纠正两轮。

以下情况应提前停止：

- 相同的阻塞原因反复出现；
- 修改需要扩大任务范围；
- 继续尝试会产生明显风险；
- 无法取得必要的验证证据。
